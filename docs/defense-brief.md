# Контекст дипломной работы — брифинг для LLM

Этот документ — краткая, самодостаточная сводка дипломной работы для передачи языковой модели, чтобы она могла отвечать на вопросы по защите диплома. Содержит: суть работы, ключевые числа, главные результаты, готовые ответы на типовые вопросы преподавателя.

## Что это за работа

**Тема:** Автоматическая классификация фотографий по визуальному стилю на основе transfer learning.

**Уровень:** Выпускная квалификационная работа бакалавра, ЯрГУ им. П.Г. Демидова, направление 02.03.02 Фундаментальная информатика и информационные технологии.

**Год:** 2026.

**Цель:** Разработать программный комплекс, выполняющий стилевую классификацию фотографий, и провести углублённый эмпирический анализ обученной модели.

**Девять задач** (все выполнены): обзор методов; сбор и разметка датасета; обучение нейросети; проектирование микросервисной архитектуры; REST-API; клиентское веб-приложение; контейнеризация и CI; шесть исследовательских экспериментов; формулировка направлений развития.

## Архитектура системы

Пять компонентов:

1. **React SPA** (фронт, Vite, порт 5173) — регистрация, загрузка фото, галерея, модалка с анализом.
2. **Spring Boot 3 backend** (Java 17, порт 8080) — REST API, JWT-авторизация, оркестрация задач.
3. **FastAPI ML-сервис** (Python 3.11 + PyTorch, порт 8000) — инференс EfficientNet-B0, извлечение embedding'ов, palette + score-card.
4. **PostgreSQL 16** — метаданные пользователей, фото, связи photo↔style.
5. **MinIO** (S3-совместимое) — объектное хранилище изображений.
6. **RabbitMQ** — брокер для асинхронной передачи задач между backend и ML.

Всё контейнеризовано в **Docker Compose**, CI через **GitHub Actions**, 11 интеграционных тестов через **Testcontainers**.

**Поток данных при классификации фото:** клиент → backend (валидация, MinIO, запись в БД статус PENDING) → RabbitMQ → ML-сервис (скачивает из MinIO, инференс, публикует результат) → backend (consumer, обновляет БД статус DONE) → клиент видит теги через polling.

## Датасет

- **Источники:** Unsplash и Pexels API (поиск по ключевым словам — weak supervision).
- **Объём:** 4691 фотография после очистки.
- **Классы (8):** `airy, dark, dramatic, golden_hour, minimalist, monochrome, neon, vintage` (в алфавитном порядке — это важно, потому что `ImageFolder` индексирует так и индексы должны совпадать с порядком классов в production-сервисе).
- **Предобработка:** MD5-дедупликация (удалено 102 дубля), cap до 600 фото на класс с детерминированным `random.seed(42)`, `minimalist` отдельно cap до 500.
- **Финальное train/val разделение:** 80/20, stratified, `seed=42`. Итого: 3556 train + 893 val.

### Эволюция таксономии

| Итерация | Классы | Best val acc | max/min баланс | Bias-эффект |
|---|---|---:|---:|---|
| v1 | 8 с `moody`, `street` | 0.678 | 5.0× | сильный на `minimalist` |
| v2 | 7 без `street` | 0.724 | 1.9× | заметный на `moody` |
| v3 | 8 (+`monochrome` +`neon`, −`moody`) | 0.726 | 1.2× | устранён |
| **v3.1** | та же, воспроизводимый split | **0.694** | 1.2× | устранён |

**Удалили `street`** — это жанровая категория (улица, документальная съёмка), не стилевая. **Удалили `moody`** — методологически слабый, систематически путался с `dark`, `dramatic`, `vintage`. **Ввели `monochrome` и `neon`** — операционально определимые через статистики (saturation).

### Data leakage и v3 → v3.1

Это **методологическая фишка работы**. В оригинальном обучении v3 (val_acc=0.726) split хранился в эфемерной файловой системе Colab и был утрачен. При попытке воспроизвести его на том же `seed=42` получился **другой** val (порядок `iterdir()` Drive нестабилен относительно `random.shuffle()`). На «реплицированном» val старая модель показала **завышенные** 0.925 — это data leakage: ~30% новых val-фотографий были train-фотографиями оригинальной модели.

**Решение:** алгоритм воспроизводимого split'а через `sorted()` + полное переобучение → v3.1, **честные 0.694** на воспроизводимом val. Снижение на 3 пп от оригинальных 0.726 лежит в пределах статистической дисперсии.

### Гиперпараметры обучения v3.1 (точно те же, что у v3)

- Архитектура: EfficientNet-B0 (5.3M параметров, 16 МБ чекпоинт)
- Phase 1 (5 эпох): только классифицирующая голова, lr=10⁻³, AdamW, weight_decay=0.01
- Phase 2 (25 эпох): full fine-tune, lr_backbone=10⁻⁴, lr_head=10⁻³, CosineAnnealingLR
- Loss: CrossEntropyLoss с label_smoothing=0.1
- Sampler: WeightedRandomSampler (1/count_c)
- Аугментации train: RandomResizedCrop(224, scale=(0.7,1.0)) + HorizontalFlip + ColorJitter(0.15,0.15,0.15,0.05)
- Mixed precision (`torch.amp.autocast`), batch_size=32
- Early stopping patience=7

Best epoch: phase 2 epoch 12, val_acc=0.694.

## Шесть углублённых экспериментов (E1–E6)

### E1. Grad-CAM (интерпретируемость)

Самостоятельная реализация через PyTorch hooks. Подтверждено, что модель смотрит на стилистически осмысленные области: засветы для `golden_hour`, неоновые пятна для `neon`, равномерное внимание для `monochrome`. Анализ топ-10 «уверенно неправильных» предсказаний — case study типовых ошибок (например, чёрно-белый портрет → модель колеблется между `dark` и `monochrome`, потому что фото объективно соответствует обоим).

### E2. Embedding-пространство (t-SNE/UMAP)

Извлечены 1280-мерные эмбеддинги для всех 893 val-фото.
- **Silhouette score: 0.026** (низкий — классы перекрываются)
- **Davies-Bouldin: 6.24** (высокий — то же подтверждение)
- **k-NN5 accuracy на сырых эмбеддингах: 0.618** — всего на 7 пп ниже full модели. Значит **большая часть классифицирующей способности находится в самих представлениях**, а не в финальной голове.

Низкий silhouette не значит «модель плохая» — он значит «классы по природе перекрываются», что и ожидалось для стилевой задачи.

### E3. Score-card baseline на ручных признаках

Для каждой фотографии считаются 5 детерминированных метрик: brightness, contrast, saturation, warmth, sharpness.

**ANOVA значимость:** F-статистики 70.6 (sharpness) — 501.1 (brightness), p-value 5×10⁻⁹⁷ до < 10⁻³⁰⁰. Все 5 метрик статистически значимо различаются между классами.

**Baseline-классификаторы на этих 5 признаках:**
- Logistic Regression: accuracy 0.478, macro F1 0.447
- Random Forest: accuracy 0.489, macro F1 0.478
- **EfficientNet-B0 v3.1 (CNN):** accuracy **0.694**, macro F1 **0.687**

Случайное гадание = 0.125 (1/8). RF в **~4 раза** лучше random — это значит таксономия операционально определима. CNN добавляет **+20 пп** сверх ручных признаков — это **вклад глубоких представлений** (композиция, текстуры, контекст). Это **оправдывает использование CNN**.

### E4. Калибровка вероятностей (temperature scaling)

Метод Guo et al. 2017. Найдена скалярная температура T=1.094 (модель **слегка** переуверена) и вектор T_c ∈ [0.746; 1.338] для per-class scaling.

- **ECE до:** 0.061 → **после vector scaling:** 0.049 (−20%)
- **MCE до:** 0.458 → **после vector:** 0.300 (−35%)
- **Brier:** 0.452 → 0.448
- **NLL:** 0.982 → 0.956

Accuracy остаётся 0.694 — это **ожидаемо**, цель калибровки не точность, а соответствие показанной уверенности реальной accuracy.

### E5. Сравнение с CLIP (foundation model)

CLIP ViT-B/32 от OpenAI, обучен на 400M пар (изображение, текст).

| Подход | Accuracy | Macro F1 | Размер | Обучение |
|---|---:|---:|---|---|
| EfficientNet-B0 v3.1 fine-tune | 0.694 | 0.687 | 16 МБ | 2-фазный fine-tune ~30 мин T4 |
| **CLIP linear probe** | **0.738** | **0.730** | 350 МБ | sklearn logreg <1 мин CPU |
| CLIP zero-shot | 0.635 | 0.616 | 350 МБ | без обучения |

**Главный неожиданный результат:** CLIP linear probe **превосходит наш fine-tune на +4.4 пп** при том, что не требует переобучения. Это **negative result для собственной модели** — мы честно фиксируем его и формулируем как направление развития (переход на CLIP в production).

Zero-shot интересен: без размеченных данных даёт 0.635. Лучше всего работает на «текстуальных» классах (`neon` F1=0.934, `golden_hour` F1=0.793), плохо — на абстрактных (`dramatic` F1=0.244).

### E6. Multi-label расширение

Гипотеза: single-label некорректен для composite фотографий. Эмпирическая проверка через переход на BCEWithLogitsLoss + sigmoid + per-class threshold tuning. Автогенерация co-меток через score-card правила (порог по saturation для monochrome, brightness для dark/airy и т.д.). После применения правил **56.8% фото получают ≥2 меток**.

**Результаты v4 (multi-label):**
- **mAP = 0.818** (mean Average Precision)
- **Macro F1 = 0.773** (vs 0.687 у v3.1)
- **Exact-match accuracy = 0.529** (53% фото получают **весь набор меток** правильно)
- **Hamming accuracy = 0.920** (92% бинарных решений правильны)

**Per-class сравнение single → multi:**

| Класс | v3.1 F1 | v4 F1 | Δ |
|---|---:|---:|---:|
| **monochrome** | 0.545 | **0.934** | **+38.9 пп** |
| **dark** | 0.598 | **0.881** | **+28.3 пп** |
| dramatic | 0.537 | 0.610 | +7.3 |
| airy | 0.722 | 0.756 | +3.4 |
| minimalist | 0.621 | 0.640 | +1.9 |
| vintage | 0.737 | 0.716 | −2.1 |
| golden_hour | 0.831 | 0.810 | −2.1 |
| neon | 0.904 | 0.838 | −6.6 |

**Главный результат:** `monochrome` превращается из самого слабого класса (F1=0.545) в самый сильный (F1=0.934). Это эмпирическое подтверждение того, что single-label постановка была **методологически некорректна** для composite классов. Чистые операционально-изолированные классы (`neon`, `golden_hour`) слегка теряют от расширения разметки — это нормальный trade-off.

## Главные результаты для защиты (5 точек)

Это то, что нужно проговорить **обязательно** на защите. Самое сильное в работе.

### 1. Обнаружение и исправление data leakage (v3 → v3.1)

Методологически зрелый результат — большинство студентов публикуют первый полученный val_acc. Я провёл диагностику, реализовал воспроизводимый алгоритм split'а, переобучил модель. Сравнение v3 (0.726) и v3.1 (0.694) показывает что **методологические выводы работы устойчивы к перетасовке данных** — это сильный аргумент при защите.

**Готовая формулировка:**

> Модель устойчива к перетасовке валидационной выборки: изменения per-class F1 не превышают 9 процентных пунктов между независимыми обучениями на одном датасете, при этом общая структура ошибок и иерархия сложности классов сохраняются. Это подтверждает, что наблюдаемые закономерности — методологические свойства задачи и таксономии, а не артефакты конкретного train/val split'а.

### 2. Операциональная определимость классов

ANOVA F=70–501, p < 10⁻⁹⁷ для 5 score-card метрик. Baseline на 5 ручных признаках 0.489 (в 4 раза лучше random 0.125), CNN добавляет +20 пп. **Это формальная характеризация таксономии**, не «выдуманные» категории.

### 3. CLIP linear probe > наш fine-tune (negative result, честно зафиксирован)

+4.4 пп без обучения. Формулируется как направление развития, не как недостаток работы.

### 4. Multi-label трансформация monochrome

F1 = 0.545 → 0.934 (+38.9 пп). Самый драматический per-class прирост в работе. Эмпирическое подтверждение методологической гипотезы.

### 5. Grad-CAM подтвердил интерпретируемость

Модель опирается на стилистически осмысленные области, а не на shortcut-паттерны. Это **валидация модели**, не «применил визуализацию».

## Готовые ответы на типовые вопросы преподавателя

### Q1. Почему EfficientNet-B0, а не другая архитектура?

Баланс точности и эксплуатационных характеристик. При параметрах сравнимых с MobileNet (5.3M) даёт +2.5 пп Top-1 на ImageNet. Размер 16 МБ против 100 МБ у ResNet-50 позволяет CPU-инференс без GPU. ResNet-50 даёт +5 пп точности, но в 6 раз тяжелее и в 3 раза медленнее.

### Q2. Что такое transfer learning?

Переиспользование модели, обученной на одной задаче, для другой связанной. EfficientNet-B0 на ImageNet выучила базовые признаки — текстуры, градиенты, формы. Я заменил классифицирующий слой на 8 нейронов и продолжил обучение на своём датасете. Низкоуровневые признаки переиспользуются, верхнеуровневое представление адаптируется под стилевые признаки.

### Q3. Что такое embedding?

1280-мерный вектор из предклассифицирующего слоя (выход global average pooling). Используется backend'ом для поиска похожих фотографий через cosine similarity. Точнее, чем поиск по совпадению top-1 тегов — два фото могут иметь разные top-1, но быть очень близкими в embedding space.

### Q4. Почему двухфазный fine-tune?

Если разморозить backbone сразу, ранние большие градиенты от случайно инициализированной головы разрушают предобученные представления. Phase 1 (5 эпох, только голова) стабилизирует — голова догоняет распределение классов. Phase 2 (25 эпох, всё) дообучает совместно с пониженным lr.

### Q5. Что такое Grad-CAM?

Gradient-weighted Class Activation Mapping. Forward pass с сохранением активаций target-слоя, backward pass от логита класса, усреднение градиентов по пространственным осям даёт веса каналов, взвешенная сумма активаций даёт heatmap. Показывает на какие области изображения смотрит модель для конкретного предсказания.

### Q6. Почему 0.694, а не 0.726 как в оригинале?

Это разные val-выборки. Оригинальный split v3 утрачен (был в эфемерной FS Colab). На воспроизводимом split'е v3.1 даёт 0.694. Разница 3 пп — статистическая дисперсия для 893 фото. Главное — иерархия классов сохраняется между обучениями.

### Q7. Multi-label vs single-label — в чём разница?

Single-label: один правильный класс на фото, softmax, argmax. Multi-label: несколько классов одновременно, sigmoid, бинарное решение по каждому. Для стиля single-label некорректен — фото может быть и monochrome и minimalist одновременно. Переход к multi-label поднимает F1 monochrome с 0.54 до 0.93.

### Q8. CLIP linear probe > ваш fine-tune. Не унижает?

Нет — это **результат исследования**, а не недостаток работы. CLIP обучен на 400M пар (image, text) с естественной языковой разметкой; его представления уже включают стилевые концепты. Мой fine-tune EfficientNet адаптирует ImageNet-представления (object recognition), которые изначально не рассчитаны на стилевую семантику. Я провёл честное сравнение и зафиксировал это как направление развития. Для production выбран EfficientNet-B0 из-за компактности (16 МБ vs 350 МБ) и скорости CPU-инференса.

### Q9. Почему собрали свой датасет, а не использовали AVA или Flickr-Style?

AVA — это aesthetic scoring (численная оценка красоты), не классификация по стилям. Flickr-Style имеет 20 категорий, многие — технические артефакты (HDR, Bokeh, Macro), а не стили. Сбор собственного датасета с явной операциональной таксономией 8 классов даёт более чистую постановку задачи. Методологически следую подходу Flickr-Style — дискретная таксономия + supervised classification — но с собственной формализацией.

### Q10. Зачем temperature scaling, если accuracy не меняется?

Цель не точность, а калибровка. Без калибровки confidence 80% может означать реальную accuracy и 65%, и 90%. После scaling — означает реально ~80%. ECE упал с 0.061 до 0.049 (−20%), MCE — с 0.458 до 0.300 (−35%). Это критично для UI (пользователь видит честные проценты) и для production-пайплайнов с порогами уверенности.

### Q11. Где будет применяться система?

Курация цифровых фотоархивов, обучающие материалы по компьютерному зрению, исследовательские прототипы. Embedding-API для интеграции поиска похожих в сторонние приложения. Лицензия MIT.

### Q12. Чем отличаетесь от Pinterest/Google Photos/Adobe Lightroom?

У Pinterest и Google Photos классификация по объектам, не стилям. Adobe Lightroom имеет несколько стилевых тегов как маркетинговую функцию, без декларируемых метрик и без open-source. Моя система — единственная open-source, self-hosted, специализированная на стиле, с embedding-API.

### Q13. Сколько кода написано, сами ли всё писали?

Около 250 файлов, ~15 МБ исходного кода. Backend Spring Boot (Java, 11 интеграционных тестов), ML-сервис на Python с собственной реализацией Grad-CAM через PyTorch hooks, React фронт, 9 скриптов обучения и экспериментов, документация, конфигурации. Использовал AI-ассистенты, документацию, Stack Overflow — стандартный современный пайплайн разработки. Главное — понимаю каждую строку и каждую методологическую решение, могу объяснить любой фрагмент.

### Q14. Какие ограничения у работы?

Главное — размер датасета 4500 фото; для глубокого обучения это маленький объём, отсюда высокая дисперсия per-class метрик. Второе — multi-label метки сгенерированы автоматически через score-card правила, а не размечены вручную (формулирую как направление развития: ручная разметка 500–1000 фото). Третье — один train/val split, не k-fold (компенсировано сравнением v3 vs v3.1 как двух независимых обучений).

### Q15. Что бы вы сделали по-другому?

Главные три:
1. Сохранил бы split вместе с весами в постоянное хранилище с самого начала, чтобы избежать ситуации с data leakage (этот урок уже включён в направления развития).
2. Размечал бы multi-label вручную с самого начала, чтобы не зависеть от автогенерируемых правил.
3. Использовал бы k-fold cross-validation для получения confidence intervals на per-class метриках.

## Признание ограничений (важно для честной защиты)

Не маскируем слабые места:

- **Размер датасета 4500 фото — маленький.** Отсюда высокая дисперсия per-class F1 (−9 пп ± между независимыми обучениями для некоторых классов).
- **Multi-label разметка автоматическая, не ручная.** Пороги в правилах эмпирические, могут не совпадать с экспертной оценкой. Результаты multi-label следует читать как «верхняя эмпирическая граница потенциала, достигаемая при идеальной разметке».
- **Один train/val split, не k-fold.** Компенсация через сравнение v3 и v3.1 как двух независимых обучений.
- **Foundation-модель CLIP превосходит наш fine-tune.** Честно фиксируем, формулируем как направление развития.
- **Out-of-distribution на пользовательских снимках.** Модель обучалась на стоковых фото; на мобильных селфи и бытовых снимках работает хуже.

## Шесть направлений развития

1. Ручная multi-label разметка ~1000 фото с оценкой межрейтинговой согласованности.
2. Переход на CLIP linear probe в production при наличии GPU-инференса.
3. Fine-tune CLIP методом LoRA для получения дополнительного прироста на собственном датасете.
4. Векторный поиск похожих через pgvector с HNSW-индексом для масштабирования к 100K+ фотографий.
5. Stratified k-fold cross-validation для получения confidence intervals.
6. Persistent split — сохранение train/val списков рядом с весами в постоянное хранилище (Drive, S3), а не в эфемерную FS среды обучения.
